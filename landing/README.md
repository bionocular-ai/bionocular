# Bionocular landing page

The public marketing page served at https://bionocular.ai from Cloudflare Pages. Static HTML, CSS and vanilla JS, no framework.

## Structure

```
landing/
├── index.html              page markup
├── styles.css              hand-written styles
├── script.js               behaviour (nav, headline rotator, hero heatmap, product diagram, survival chart)
├── data/                   survival twin curves, generated by melanoma/scripts/export_landing_km.py
├── _headers                Cloudflare Pages headers (CSP and security headers)
├── fonts/                  self-hosted Onest (headings), Poppins (text), IBM Plex Mono (data) and Plus Jakarta Sans (wordmark), with licences
├── logo.svg, icon.svg, favicon.ico, apple-touch-icon.png, og.jpg
```

## Local development

```bash
cd landing
python3 -m http.server 8000
```

Then open http://localhost:8000.

There is no build step. After changing `styles.css`, `script.js` or the data file, bump their `?v=` strings in `index.html`.

## Survival chart data

The Survival Intelligence chart and the comparison-table sparkline draw the CheckMate 067 PFS digitized twins from `data/km-checkmate067-pfs.js`. The page has no database access, so the curves ship as a static file. Regenerate it from `km_curves` when the twins change:

```bash
cd melanoma && poetry run python3 scripts/export_landing_km.py
```

## Deployment

Cloudflare Pages deploys from this repo on every push to `main`:

| Setting | Value |
| --- | --- |
| Repository | `bionocular-ai/bionocular` |
| Production branch | `main` |
| Root directory | `landing` |
| Build command | none |
| Build output directory | `.` |
| Build watch paths (include) | `landing/*` |

The watch path keeps commits to `web/` and `melanoma/` from triggering a landing redeploy.

When adding a third-party script, image host or analytics beacon, allow it in the CSP in `_headers` or the browser will block it.
